Repo: `harness-reasearch/kvc/`; runs under `results/kvc/` (gitignored).

## 1. Question and framework

**Thesis (K layer)**: strong models hold latent task knowledge; coding agents
fail to convert it into successful runs. The failure is decomposed into phase
transitions with per-phase success probabilities p_D · p_I · p_V · p_T:

- **D**iagnosis: know what is wrong / where to edit;
- **I**nitiation: actually mutate the workspace;
- **V**erification: check the mutation against an oracle;
- **T**ermination: stop on verified success.

Success S = D ∧ I ∧ V ∧ T. The KVC harness instruments a fixed model
(**qwen3.8-flash, thinking off**, frozen for the whole program) inside the pi
coding-agent harness: GPS machine facts, mutation epochs via git
fingerprints, triggers T1 (≥35% budget, zero mutations), T2 (validation
fail), T3 (post-pass drift), event-triggered fresh-context checkpoint probes
that produce JSON decision cards `{invariant, edit_surface, minimal_change,
falsifier, next_action}`, steered replace-in-place (K layer), and a frozen
overlay validator `validate_current_patch` (V layer).

## 3. Rounds

### R1/R1b — KAC on the ceiling task (pi-retry-attempt-timeout)

KAC hooks ran live with checkpoint probes. Findings: (i) triggers are rare on
a task the model solves 60% of the time (most runs never hit T1/T2), so the
ceiling task is the wrong substrate for steering measurements — per GPT
critique, moved to 20–60%-band tasks; (ii) probe infrastructure defects
found and fixed (tools=() leakage, extraction via agent_end fallback,
teardown race). Zero successful card injections at ceiling — interpreted as
trigger scarcity, not KAC failure.

Baseline established alongside: post-sanitization clean natives = 3/5 pass
(each run independently audited for leaks). Control-loss probes: once the
patch passes, agents settle within seconds ⇒ termination is NOT the
bottleneck on this task (p_T ≈ 1).

### R2 — DEV natives: mutation-initiation failure

Three harder tasks (each 0/3 clean natives; find-root 1/3 settled but 0/3
clean-settled) show a consistent signature: long read/bash exploration, zero
or near-zero edits, T1 firing in a tight band. Adopted terminology
(mutation-initiation failure, D→I collapse) per external critique; claims
kept observational. These tasks became the R3–R5 substrate.

### R3 — trigger-time fork: cards at deterministic checkpoints (priority design)

Pre-registered in DESIGN-FORK.md. Donors run pure-native; at each trigger the
harness freezes a fork spec (APFS clonefile snapshot, session JSONL, GPS,
remaining budget). Children restart from the frozen state (pi `--fork` exact
transcript replay, validated byte-identical) in three arms × 2: **none**
(pure continuation), **sham** (format-identical content-free card), **kac**
(card generated by a fresh-context probe from the frozen state). Primary
outcome: any validation pass.

**Result: 0/30 children passed in every arm, every block** (20 included after
quarantines: 6 b3 children dropped by donor harness-tier contact, 3 none-arm
children by their own behavioral gold contact; 1 kac-nocard labeled
separately). Cards themselves worked: after a template fix (probes without
tools role-played tool calls until an explicit no-tools directive), 9/10 card
probes settled → parsed → steer accepted, naming the correct edit surface.
Block diffs [0,0]; Hodges–Lehmann 0; permutation p=1.0 non-decisional
(exact-p floor 0.5 with 2 informative blocks — estimation-only, as
pre-registered).

**Reading**: on find-root the chain breaks AFTER card delivery. Children of
all arms mutated at similar rates (~3–4 epochs/child) but produced only 4
validation calls across 20 children and zero passes within remaining budgets
(118–284 s). Converges with the donor decomposition (below): the binding
transitions are I→V and V-capacity, not knowledge discovery and not card
acceptance. Null stated in bounds language per pre-registration.

### R4 — know≠act: fresh-context D-probes on zero-mutation runs

Protocol (pre-registered wording in notes/hysteresis-r4-plan.md): for clean
runs with zero mutations, a fresh-context D-probe at C0 receives only the
state (task, GPS, file index) and must name the edit surface; the denominator
is conditioned on probe ANSWERABILITY, with censoring reported separately.

Result under the unified final protocol (full file index in prompt, 5-read
cap, 360 s, fixed extraction):

- find-root: probe on the zero-mutation native run settled, parsed, named the
  gold surface (`find.ts` relativization sites) — **know≠act positive**; an
  earlier-vintage probe on the donor run gave the same answer (its rerun
  settled with substantively correct but malformed JSON → censored under the
  frozen definition, noted qualitatively). KNAct = 1/1 answerable.
- thinking-toggle + post-tool-compaction: probes still budget-censored
  despite the file index (3/5 censoring overall, 80%).

The pre-registered probe-reliability gate (no kill/keep decision while
censoring > 20%) therefore blocks any verdict on the Agent-Hysteresis kill
criterion (<2% equivalent-state divergence); the criterion stands **in force
but untested**. What R4 does establish: state-only diagnosis CAN name the
gold edit surface where the history-carrying actor made zero mutations — the
divergence is observable with current instrumentation; the binding constraint
is probe answerability, not the effect size.

### R5 — knowledge vs initiation decomposition (COMPLETE, batch r5-rescue-2)

DESIGN-R5.md. Arms on the two DEV tasks: native 0-baseline (clean runs only)
vs **kac**@T1 (probe card) vs **hint**@T1 (oracle card naming the gold
surface — initiation-ceiling probe, never pooled with KAC). Rescue rules
pre-registered: hint-rescue without kac-rescue ⇒ knowledge bottleneck;
neither rescues ⇒ bottleneck beyond surface knowledge; kac-rescue ⇒ probe
machinery suffices. Baselines under the hardened audit: thinking-toggle 0/2,
compaction 0/2 clean natives. First attempt died wholesale at workspace
preparation (dependency-cache incident, §4.2); rescue batch ran on the
rebuilt read-only cache, 8/8 jobs completed, full table in
`analysis/round-5.md`.

**Result: ZERO passes in every arm under every inclusion variant ⇒ neither
rescues ⇒ pre-registered verdict: the bottleneck is initiation/execution
beyond surface knowledge.** Key process facts:

- kac: 3/4 probes produced cards (fast, 4.9–6.5s), all accepted, ALL with
  `next_action: probe`; clean-arm children made 0 edits afterwards. tt-r1
  probe emitted prose, no card (R4 censoring class).
- hint (oracle): first mutations at @271–349s (card lands ~153s) — even the
  oracle buys 120–200s of initiation latency; one replication never mutated.
  Mean epochs hint 3.0 vs kac 0.5: the oracle lifts mutation activity but
  converts to no passes.
- The batch's single validation call validated the UNMUTATED tree 6s after
  the oracle card (fail — the red-at-base signal only the overlay validator
  produces), then 6 mutation epochs with no re-validation: I→V collapse in
  both directions.
- One kac run excluded gold-tier: its FIRST tool call (t=7s, parallel with
  `pwd`) cd'd into the pi checkout — the gold location came from pi's own
  system prompt (§4.2 item 5).

## 4. Cross-cutting findings

### 4.1 Donor phase taxonomy (find-root, n=16 donors, notes/phase-donors.md)

- 14% T1-stall (zero mutations, exploration only);
- **71% mutate-without-validate churn** — the dominant shape;
- 14% reached validation (both verdicts FAIL);
- **0% ever passed** (p_T unobservable on this task from natives).
Validation never enters the edit→test inner loop; it appears as a single
"just try the button" call after long archaeology bursts — sometimes on an
empty tree. The fork children reproduce the same I→V collapse.

### 4.2 Leak channels and integrity (continuous)

Actor bash is unsandboxed; leak control is audit + quarantine, with three
hardening iterations this session (all pre-data w.r.t. the affected
outcomes):

1. **Audit strengthened** (notes/fork-integrity-review.md A5): result blobs
   scanned too (env dumps print what args never name); self-attribution is
   component-boundary path-prefix matching (fork child ids embed donor ids —
   the old substring skip leaked sibling paths); result-phase-only gold hits
   earn harness tier (passive PATH printout), args-phase hits earn gold
   (behavioral navigation).
2. **Passive disclosure found**: agent-dir/bin symlinks into the pi
   checkout's node_modules/.bin, so EVERY PATH/env dump discloses the gold
   checkout's location; 3 none-arm fork children demonstrably followed that
   disclosure to the gold tree and were quarantined. Scrubbing agent-dir/bin
   is a prerequisite for any future donor batch.
3. **Dependency-cache incident**: the shared node_modules store was corrupted
   mid-session because workspaces symlink into it (actor npm activity);
   rebuilt from the pi checkout and made read-only (notes/dependency-cache-incident.md).
4. Spawn/analysis gates: identity bind + QUARANTINE exclusion + tier checks
   at spawn; idempotence skip of finished children; child self-audit gate;
   quarantined specs' paths nulled. Audit self-attribution fixed once more
   pre-R5-scoring (path-extent expansion; direction conservative).
5. **System-prompt disclosure (found in R5, affects the whole program)**:
   pi's system prompt embeds absolute doc paths resolved from the running
   source tree (`getPackageDir()` → the pi checkout), and the actor PATH
   contains `pi/node_modules/.bin` — so EVERY run's initial context named
   the gold location. R5's gold-excluded run proves actors can act on it in
   their very first tool call. The per-run audit tier is the control and it
   held (no pooled statistic includes an un-audited or gold-tier run).
   Future-batch fixes (both one-line, pre-data when applied):
   `PI_PACKAGE_DIR=<workspace>/packages/coding-agent` (supported override —
   docs then resolve inside the actor's own base clone) and removing the pi
   checkout's .bin from the actor PATH.

Rates: 2/16 donors behavioral gold (12.5%), 3/16 harness-tier (incl. the
b3 donor that read its own validator task.json — its whole block
quarantined). No statistic in this program pools a run whose donor or self
audit is not clean (gold children excluded; harness children flagged with a
sensitivity listing).

## 5. Interpretation

1. **The Declarative-to-Procedural gap is real but located downstream of
   diagnosis on these tasks.** Fresh-context state-only probes name the gold
   edit surface when the actor with full history makes zero mutations (R4);
   yet handing that exact knowledge to the frozen-state continuation as a
   card (R3), or even naming the gold surface outright (R5 hint arm: 0/4
   passes, first edits only after 120–200 s latency), does not buy passes.
   Knowing where to edit is not the binding constraint within 118–420 s
   budgets at this model tier.
2. **The binding transitions are I→V and V-capacity**: agents mutate without
   validating (10/14 donors; 4 validation calls across 20 fork children;
   R5's single validation call landed on the UNMUTATED tree and was never
   repeated after 6 mutation epochs). Validations at base fail (oracle-gap:
   no stock command produces a failing signal; only the overlay validator is
   red at base, and actors rarely dare it — and not after mutating).
3. **Initiation itself carries a latency floor on DEV tasks**: even oracle
   knowledge at T1 (~153 s) yields first edits at @271–349 s, and one of
   four hint replications never mutated at all. The card/oracle changes WHAT
   the agent eventually touches, not how quickly it starts touching.
4. **Termination is not the bottleneck** (control loss ≤ ~21 s on the
   ceiling task), completing the p_D·p_I·p_V·p_T profile for this program's
   tasks: p_T ≈ 1, p_D high (probes name the surface), p_I low with a delay
   floor, p_V very low in both onset and placement.

## 6. Limitations

- Small n everywhere; the fork primary contrast is estimation-only by
  construction (floor 0.5). All nulls are bounds statements.
- Single model/tier (qwen3.8-flash, thinking off) — by design frozen; no
  generalization to stronger models is claimed.
- Replay stratum shrank under integrity audits (b3 quarantined) — the price
  of leak control; the decision rules were pre-registered.
- Probe answerability (80% censoring on large-file tasks) limits R4 to a
  demonstration, not a rate.
- filesystem remained an open leak channel throughout; audits catch but do
  not prevent access (future: sandbox-exec arm).
- Retroactive caveat for ALL rounds (§4.2 item 5): every actor's initial
  context disclosed the gold location via pi's system prompt. Every pooled
  statistic is still computed from audit-clean runs only, and the R5
  gold-exclusion shows the audit detects behavioral uptake; but clean tier
  means "did not act on the disclosure," which is weaker than "could not
  have seen it." All conclusions are stated under that reading.

## 7. Next steps (recommended, not executed this session)

   workspace's packages/coding-agent and drop `pi/node_modules/.bin` from

2. **Probe reliability**: enforce tool-call caps in the harness (advisory
   caps did not hold) to push D-probe answerability past the 80% gate before
   any hysteresis verdict.
3. **V-layer steering**: the data implicate validation initiation, not
   knowledge — a follow-up arm that steers "run validate_current_patch now"
   at T1 (verification-onset treatment) tests the I→V hypothesis directly,
   with n_validate_calls and first-validate time already instrumented.
4. Engineering: sandbox-exec wrapper for actor bash; probe output schema
   hardening (malformed-JSON recovery was left OUT of scoring deliberately).
